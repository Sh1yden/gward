## [0.3.0] - 2026-11-19

### Добавлено

- Вывод в JSON (`--json`): массив репозиториев с полями `name`,
  `path`, `branch`, `status`, `staged`, `modified`, `untracked`,
  `ahead`, `behind`, `error`. Работает для `gward`, `gward fetch`
  и вместе с `-d`.
- Опция `--exit-code`: `0` — всё чисто, `1` — локальные правки
  или рассинхронизация, `2` — ошибки git. Без флага код
  возврата прежний, всегда `0`.
- Опция `--depth` для поиска во вложенных группах проектов.
  По умолчанию `1` — корень и прямые подпапки.
- Автодополнение для Bash, Zsh и Fish (`--install-completion`,
  `--show-completion`).
- Тесты для JSON, кодов возврата, глубины поиска и completion.
- Smoke-тест установленного wheel в CI: проверка CLI, JSON,
  `--depth`, completion и кодов `0/1/2`.

### Изменено

- CI разделён на независимые джобы `lint`, `typecheck`, `tests`
  и `smoke`, чтобы падение было видно отдельно.
- CI запускается на теги `v*` и вручную через `workflow_dispatch`,
  а не на каждый push в `main` и pull request.
- `find_repos` принимает глубину поиска; внутрь найденного
  репозитория поиск не спускается, скрытые папки и симлинки
  пропускаются.
- В `--json` время из `--debug` печатается в stderr, чтобы stdout
  оставался чистым JSON.
- Обновлены `README.md`, `README.en.md` и `CHANGELOG.md`.

## [0.2.0] - 2026-11-18

### Добавлено

- CI (`.github/workflows/ci.yml`): `ruff`, `mypy` и `pytest`
  на каждый push и pull request.
- `ruff` и `mypy` в dev-зависимостях, настройки линтера
  и проверки типов в `pyproject.toml`.
- Тесты для поиска репозиториев (`tests/test_dir.py`),
  CLI-опций (`tests/test_cli.py`), изоляции сбоев, таймаута,
  окружения git и компактного вывода ошибок. Итог: 63 passed.
- Секция `Errors:` под таблицей: полный текст ошибки, если
  в колонке Sync она сокращена.
- Сообщение `All repositories are clean` при `-d`, когда
  проблем не найдено.

### Изменено

- Глобальные опции указываются до подкоманды:
  `gward -C DIR fetch`. Порядок `gward fetch -C DIR` больше
  не поддерживается.
- Ошибки git в таблице сокращаются до первой строки; полный
  текст выводится под таблицей в секции `Errors:`.
- Фильтрация `-d` вынесена из `gather_statuses` в `_report`,
  поэтому пустая папка и папка без проблем различаются.
- `pyproject.toml` — заполнены метаданные пакета: описание,
  лицензия MIT, ссылки, ключевые слова, классификаторы.
- Обновлены `README.md`, `README.en.md` и `CHANGELOG.md`.

### Исправлено

- `-C`, `-d` и `--debug` теперь учитываются и для подкоманды
  `fetch`: `gward -C DIR fetch` проверяет указанную папку,
  а не текущую.
- Некорректный или несуществующий путь в `-C` даёт понятную
  ошибку с кодом 2 вместо traceback.
- Сбой одного репозитория больше не обрывает весь отчёт:
  ошибка показывается в строке этого репозитория.
- Git больше не наследует `GIT_DIR`, `GIT_WORK_TREE` и другие
  переменные контекста вызывающего процесса.
- Зависший git завершается вместе с дочерними процессами
  (группа процессов), а не только сам.
- Вывод git в не-UTF-8 кодировке больше не приводит
  к `UnicodeDecodeError`.

### Удалено

- `gward/timer.py` — пустой неиспользуемый модуль.

## [0.1.0] - 2026-11-15

### Добавлено

- Таблица статуса локальных Git-репозиториев на `rich`:
  Repository, Branch, Status, Staged, Modified, Untracked, Sync.
- Параллельный сбор статусов через семафор `asyncio`
  (до 8 одновременных процессов git).
- Команда по умолчанию `gward`: быстрая локальная проверка
  без сети.
- Подкоманда `gward fetch`: выполняет `git fetch --prune`
  во всех репозиториях и показывает обновлённый статус,
  поэтому колонка Sync отражает remote.
- Флаг `-d` / `--dirty`: показывает только репозитории,
  которые требуют внимания (ошибки, локальные правки,
  расхождение с remote).
- Опция `-C` / `--dir` для выбора папки (по умолчанию текущая).
- Флаг `--debug`: выводит время выполнения под таблицей.
- Парсер вывода `git status --porcelain=v2 --branch`
  как чистая функция.
- Тесты: парсер на фикстурах, интеграционные тесты
  на временных репозиториях с локальным bare-remote,
  тест ограничения параллельности, тесты вывода.
- `README.md` и `README.en.md`.

### Изменено

- Вывод CLI и комментарии в коде на английском.
- В колонке Sync при отсутствии upstream показывается `—`
  вместо `↑0 ↓0`, которое вводило в заблуждение.

### Исправлено

- Репозитории, у которых `.git` является файлом
  (worktree, submodule), определяются корректно.
- Зависшие процессы git снимаются по таймауту: 10 секунд
  для статуса, 60 секунд для fetch.
- Git не запрашивает учётные данные
  (`GIT_TERMINAL_PROMPT=0`) и не берёт необязательные
  блокировки индекса (`GIT_OPTIONAL_LOCKS=0`).
- Тест fetch без remote проверял неверное поведение:
  `git fetch` без remote возвращает код 0. Тест переписан
  на реальный сбой с недоступным remote.

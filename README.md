# 🛡 gward

🌐 Язык / Language **README**: **Русский** · [English](README.en.md)

![icon](assets/icon.svg)

> **Краткое описание:** 🛡️ Консольная утилита для мгновенного статуса десятков локальных Git-репозиториев: незакоммиченные правки, незапушенные коммиты и отставание от remote — одной командой.

## ❔ Зачем вообще проект?

Если у вас десятки локальных проектов, легко забыть незапушенный коммит или незакоммиченные правки. `gward` проверяет все репозитории в папке параллельно и показывает одну таблицу за доли секунды, без `cd` в каждую папку.

## 🛠 Техно-стек

- **Язык:** `Python 3.13`
- **Git-движок:** `asyncio.subprocess`, нативный `git status --porcelain=v2`
- **CLI:** `typer`
- **Вывод:** `rich`
- **Пакетный менеджер и сборка:** `uv` (`uv_build`)
- **Тесты:** `pytest`
- **Проверки:** `ruff`, `mypy`

## 💜 Руководство пользователя

### 🔽 Установка / Быстрый старт

Требования: Python 3.13, установленный `git`, Linux или macOS. Менеджер пакетов `uv`: [инструкция по установке](https://docs.astral.sh/uv/).

1. Установите `gward` из репозитория:

```shell
uv tool install git+https://github.com/Sh1yden/gward
```

1. Проверьте, что команда доступна:

```shell
gward --help
```

Для разработки см. раздел [«Разворачивание проекта»](#-разворачивание-проекта).

### 🖱 Повседневное использование

- **`gward`** — статус всех репозиториев в текущей папке. Работает локально, сеть не используется.
- **`gward -C ~/projects`** — то же самое для другой папки. Флаг `-C` работает так же, как у `git -C`.
- **`gward -d`** — показать только репозитории, которые требуют внимания: с ошибкой, с локальными правками или с расхождением с remote.
- **`gward --debug`** — добавить внизу время выполнения.
- **`gward fetch`** — сначала выполнить `git fetch --prune` во всех репозиториях, потом показать статус. Нужна сеть.
- **`gward -C ~/projects fetch`** — то же для другой папки. Глобальные опции (`-C`, `-d`, `--debug`) указываются **до** подкоманды.

Колонки таблицы:

- **Staged** — файлы, добавленные в индекс (`git add`), но ещё не закоммиченные.
- **Modified** — изменённые файлы в рабочей копии, включая конфликты.
- **Untracked** — новые файлы, которые git не отслеживает.
- **Sync** — `↑N` сколько коммитов ждут push, `↓N` сколько коммитов есть на remote, но нет локально. `—` означает, что upstream не настроен.

### ❓ Частые вопросы

- **Sync показывает `↓0`, хотя на GitHub есть новые коммиты.** Без `fetch` git не знает о коммитах на сервере: он сравнивает с сохранёнными ссылками на remote, а они устаревают. Запустите `gward fetch`.
- **В Sync стоит `—`.** У ветки не настроен upstream. Добавьте его командой `git push -u origin <ветка>`, и колонка начнёт показывать `↑` и `↓`.
- **Строка помечена `error`.** Git не смог прочитать статус или выполнить fetch. В колонке Sync показывается первая строка ошибки, полный текст выводится под таблицей. Частые причины: повреждённый репозиторий, недоступный remote, таймаут.
- **Ошибка `Invalid value for '--dir' / '-C'`.** Указанной папки не существует или это файл. Проверьте путь; `gward` не запускает проверку, пока папка не найдена.
- **Выводится «No Git repositories found».** `gward` ищет репозитории в самой папке и в её прямых подпапках. Скрытые папки (с точкой) пропускаются. Если запустить `gward` внутри самого репозитория, покажется только он.
- **Почему `fetch` — отдельная команда, а не флаг?** Обычная проверка должна быть мгновенной и не ходить в сеть. Fetch занимает секунды и зависит от сети, поэтому он запускается явно.
- **Какой remote обновляет `fetch`?** Тот, что настроен для текущей ветки (upstream, обычно `origin`). `git fetch --prune` без аргументов не обходит все remote. Это осознанно: недоступный второй remote не должен помечать репозиторий ошибкой. Для всех remote выполните `git fetch --all` вручную.
- **Пропала строка с чистым репозиторием.** Флаг `-d` скрывает все чистые репозитории, включая те, у которых не настроен upstream.
- **Выводится «All repositories are clean».** Фильтр `-d` сработал, но проблем не найдено: все репозитории чистые и синхронизированы. «No Git repositories found» остаётся только для папки, где репозиториев нет вообще.
- **Таймауты.** Обычная проверка ждёт git до 10 секунд, fetch — до 60. Если репозиторий не ответил за это время, он помечается `error`, а остальные продолжают проверяться.

## 💻 Разделы для разработчиков

### 🧰 Разворачивание проекта

1. Клонируйте репозиторий:

```shell
git clone https://github.com/Sh1yden/gward.git
cd gward
```

1. Установите окружение через `uv`:

```shell
uv sync
```

1. Установите `gward` в режиме редактирования, чтобы изменения сразу работали в команде `gward`:

```shell
uv tool install --editable .
```

### 🧪 Тесты

Тесты лежат в директории [`tests`](tests). Парсер `git status` проверяется на фикстурах с реальным выводом git, без вызова самого git. Интеграционные тесты создают временные репозитории через `tmp_path` и работают с локальным bare-remote, поэтому сеть не нужна.

```shell
uv run pytest -v
```

Линтер и проверка типов (настройки лежат в `pyproject.toml`):

```shell
uv run ruff check
uv run mypy
```

## 🗄 Структура проекта

- `gward/` — пакет приложения.
  - `main.py` — CLI на `typer`: команда по умолчанию (`gward`) и `fetch`, параллельный запуск через семафор.
  - `git.py` — запуск git (`run_git`), парсер `parse_status`, `get_status` и `fetch_repo`.
  - `dir.py` — поиск репозиториев в папке.
  - `filter.py` — приоритеты, сортировка и фильтр `only_attention` для флага `-d`.
  - `output.py` — таблица `rich` и вывод отчёта.
  - `models.py` — dataclass `RepoStatus`, описывающий состояние одного репозитория.
- `tests/` — тесты по модулям; `test_git.py` содержит интеграционные тесты на реальных репозиториях.
- `pyproject.toml` и `uv.lock` — конфигурация проекта и зависимости.
- [`README.md`](README.md) — этот файл; [`README.en.md`](README.en.md) — английская версия.
- [`LICENSE`](LICENSE) — лицензия проекта.
- `.github/workflows/ci.yml` — CI: `ruff`, `mypy` и `pytest` на каждый push и pull request.
